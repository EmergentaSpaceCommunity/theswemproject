# Architecture Decision Records

ADRs capture **durable decisions**, not task progress. Use them when a choice will constrain future
implementation and would otherwise be repeatedly rediscovered.

Each ADR should contain:

- status (`accepted`, `superseded`, `proposed`);
- context;
- decision;
- consequences;
- links to superseded/current decisions when applicable.

Do not create an ADR for every implementation detail. If a decision is temporary to one task, keep
it in the active ExecPlan.
